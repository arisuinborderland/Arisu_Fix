ARISU RECOVERY CONTACT — V_109 PATCH NOTES

Primary issue addressed
- V_108 placed scroll-reveal initialization inside the Daily Bible Verse initializer. This coupled a page-wide behavior to unrelated code and made it vulnerable to an early return or runtime error in that initializer.
- The previous IntersectionObserver threshold (0.12) could miss tall sections whose visible intersection never reached 12% of their full height.
- Some visible content in the WhatsApp/contact block, including the Recovery Proofs card, was not included by the prior selectors.

Changes
- Added an independent scroll-reveal.js loaded after script.js on index.html.
- Reduced observer threshold to 0 and used a small bottom root margin so sections start revealing as they enter the viewport.
- Uses discrete reveal targets instead of nested parent and child targets; targets include the WhatsApp notice, contact divider, all social cards, each main section, and footer items.
- Retains fade-up motion and re-reveal when scrolling back to an item.
- Continues to respect the operating system's prefers-reduced-motion setting.
- Added v109 cache-busting on the homepage CSS/JS paths.
- Kept the existing content, layout, links, review images, profile image, and other page behavior unchanged.

Checks performed
- JavaScript syntax checked with Node.js for script.js and scroll-reveal.js.
- ZIP integrity checked after packaging.
- Browser-level visual test could not be completed in this environment; please confirm on the deployed page after replacing the old deployment with this package.
